Публичный каталог и фильтры

Гость ищет путешествие по названию, выбирает область и уточняет выдачу фильтрами. Карта и список используют один набор разрешённых поездок. При переключении представления поиск и фильтры сохраняются. ТЗ, FR-07

Статус. Компоновка и основные состояния каталога согласованы в UX-01. POC-04 описывает первые две ручки публичной выдачи. Их реализация и сквозная приёмка относятся к GIS-06. Статическое демо Nuxt читает вымышленные данные. Макеты UX-01 · Бэклог GIS MVP · Текущее демо

Карта, список и область

  1. Выбрать область. При разрешённой геолокации каталог показывает ближайшие путешествия. Расстояние считается от текущего положения пользователя до первой стартовой точки первого дня. При недоступной геолокации можно выбрать город или регион либо воспользоваться последней сохранённой областью.
  2. Уточнить выдачу. Поиск по названию, область и фильтры применяются к общему набору поездок. При большом числе меток ТЗ предусматривает кластеризацию. Кластеры, позиции списка и счётчики строятся по данным, прошедшим серверную проверку прав.
  3. Выбрать поездку. В режиме карты на десктопе список виден рядом. Нажатие на метку выделяет поездку в списке. На смартфоне метка обновляет нижнюю панель с выбранной поездкой. Из панели можно перейти к полноэкранному списку.
  4. Открыть карточку. Выбранная карточка запрашивает один разрешённый снимок Travel/Geo. Дни, карта и доступные метки обновляются совместно после перепроверки.

Гость и вошедший пользователь получают каталог в гостевом контексте. Travel выдаёт кандидатов из активных снимков, Geo проверяет точные закреплённые ревизии и текущие ограничения POI, затем BFF подтверждает указатели и поколения доступа в Travel. Старт для метки берётся из закреплённой ревизии первого дня. Если право на зависимость маршрута отозвано, поездка исключается до карты, списка, агрегатов и пагинации. Поиск и фильтры

УсловиеКак работает
НазваниеПоле «Найти путешествие» ищет по названию. Введённый текст применяется к карте и списку вместе с остальными фильтрами.
Город, регион и расстояниеДля ручной области доступны город или регион. Для фильтра по расстоянию в макете предусмотрено состояние «Недоступно», когда геолокация недоступна. Центр выбранного региона не определён как замена текущей позиции пользователя.
Тип путешествияМожно выбрать несколько типов. Подходит любой отмеченный тип при соблюдении остальных условий. Выдача обновляется сразу после отметки, на кнопке виден счётчик. «Сбросить» очищает выбор и снимает ограничение по типу.
Даты и времяПользователь выбирает начало и конец, год и при необходимости часы обеих границ. Диапазон может переходить через Новый год. Календарь и часы фильтра используют пояс пользователя, рядом с полями виден пояс. Пустое время охватывает весь соответствующий день. Правило отбора при заданных часах открыто.
Дополнительные фильтрыВ макете доступны стоимость «Любая / Бесплатно / Платно», сложность, статус, цена до, длительность до, расстояние до, рейтинг от, организатор и наличие свободных мест. ТЗ также предусматривает ценовой диапазон. Данные о подтверждённых участниках и платных предложениях зависят от этапов участия и Commerce.

Фильтр типа использует вычисленный тип опубликованной поездки. Одинаковый транспорт на всех отрезках даёт этот тип. Два или больше вида транспорта дают «Комбинированный». Расчёт для каталога основан на закреплённых ревизиях Geo. Расчёт типа · Фильтры в ТЗ

Календарные даты путешествия отображаются как выбраны при создании. Если есть однозначное время сбора, основная строка в карточке показывает дату и время на месте сбора. При разных смещениях появляется строка «У тебя». При переходе через полночь или Новый год видны обе даты или оба года. Расписание и время сбора

Браузер кодирует фильтры в URL. При переключении «Карта / Список» условия и общее множество результатов сохраняются. Меню фильтров открывается поверх выдачи, сохраняя положение соседних элементов. Граница клиента и BFF

Базовая карточка. Статус расположен на обложке, даты — под названием. В нижней строке показаны участники и лимит, сложность и иконка типа с доступным названием. Для отсутствующей обложки предусмотрена системная. Состав данных первого среза API указан ниже. Состав карточки в ТЗ · Участие в путешествии и заявки

Загрузка и сбой. Пока выполняется запрос для новых условий, интерфейс сообщает об ожидании. Пустой результат показывается после успешного ответа без элементов. При сбое доступно повторное чтение с текущими условиями, а устаревший ответ не заменяет более свежую выдачу. Макеты этих технических состояний уточняются при реализации.

Операции API

Проект BFF 0.1.0. Обе ручки используют гостевой контекст даже при наличии сессии и возвращают Cache-Control: no-store и X-Request-Id. OpenAPI GIS MVP

РучкаПараметры и результат
GET /api/v1/catalog/trips
listPublicTrips		200 PublicTripPage. Общая разрешённая страница для карты и списка. Параметры bbox, cursor и limit. В строке предусмотрены trip_id, publication_id, title и start.
GET /api/v1/catalog/trips/{tripId}
getPublicTrip		200 PublicTrip. UUID поездки в пути. Один актуальный снимок с UUID публикации, названием, описанием, днями, линиями и разрешёнными POI.

bbox состоит из четырёх чисел в порядке запад, юг, восток, север в WGS 84. Пересечение антимеридиана в текущем проекте не поддерживается. limit — от 1 до 100, по умолчанию 30. cursor — непрозрачный токен для прежних фильтров и контекста. При их смене запрос начинают с первой страницы. next_cursor: null означает конец выдачи.

Ошибки и восстановление

  • 400 INVALID_REQUEST. Проверить UUID, формат области, лимит или курсор. При устаревшем курсоре начать заново с актуальными условиями.
  • 404 NOT_FOUND для карточки. Поездка отсутствует или недоступна. Клиент убирает прежнюю карточку и карту поездки. В списке недоступные поездки исключаются из успешной выдачи.
  • 503 DEPENDENCY_UNAVAILABLE. Обязательная проверка данных или прав недоступна либо снимок повторно изменился во время сборки. В публичной карточке защищённые данные скрываются до успешной проверки. Клиент может повторить актуальный GET.

При изменении опубликованного снимка BFF повторяет сборку ответа один раз. Клиент принимает самый свежий запрос для текущих фильтров и не восстанавливает устаревшие данные после отзыва. Публичная карточка перепроверяется при возврате фокуса и периодически, пока видима. Ошибки BFF и восстановление · Правила перепроверки

Открытые вопросы

  • Семантика времени. Нужно определить, как заданные часы фильтра сопоставляются с календарными датами и необязательным временем сбора, в том числе для поездок без точного времени.
  • Поиск и область. Для GIS-06 предстоит согласовать параметры по названию и другим фильтрам, правила совпадения, формат URL и источник выбора города или региона.
  • Поля выдачи. Уточнить DTO карточки, число результатов, сортировку и передачу кластеров. Подсчёт мест и платные атрибуты по этапам сверяются с Travel и Commerce.
