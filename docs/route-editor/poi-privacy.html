Приватность POI

Права на место проверяются при каждом чтении, включая карту, поиск, карточку и фотографии. Если доступ отозван, необязательная метка исчезает из слоя. Если от закрытого положения зависит геометрия опубликованного маршрута, из публичной выдачи исчезает вся поездка. OD-06

Статус. GIS-04 реализует слои, поиск, запись POI, проверку положения и чтение существующих фото за BFF. В редакторе GIS-05 можно создать POI в области поездки, открыть доступное место и посмотреть его фото. Редактор GIS-05 визуально принят. В GIS-06 публичное чтение проверяет доступ к зависимостям геометрии и выбранным меткам. Проверка опубликованного снимка · Сценарий редактора · Утверждённые решения

В этом путешествии · tripПользователь с действующим полномочием в исходной поездке scope_trip_id. В GIS MVP это владелец исходной поездки.Полномочие проверяется и у автора POI. Публичность поездки не даёт посетителю доступ к закрытому слою. Модерация использует отдельное право и аудит.

Слои и поиск. «Глобальные» (scope=global) всегда работают в гостевом контексте. «Мои» (scope=mine) показывают созданные пользователем места, к которым у него есть текущий доступ. «В этом путешествии» (scope=trip) требует права на поездку слоя и включает привязанные места и POI собственной области поездки. Для каждой POI сервер проверяет актуальную область. Поиск по имени и границам карты выполняется в пределах разрешённой выдачи.

Переиспользование. Geo сохраняет связь поездки с существующим UUID POI. Travel проверяет право на целевой черновик, Geo — доступ к POI и допустимость связи. Разрешённые глобальные места можно использовать в нескольких поездках, приватные — в своих черновиках, а trip-места — в исходной поездке. Наборы могут пересекаться и ссылаться на один объект. Что происходит при отзыве

  1. Запись изменения. Geo проверяет право на изменение текущей видимости, а для перехода в область поездки запрашивает у Travel право записи в целевую область. Изменение видимости, области, модерации или удаление меняет ревизию POI. Отзыв прав на поездку проверяется по актуальным полномочиям Travel.
  2. Карточка, слой и медиа. При новой проверке место пропадает из доступных слоёв и поиска. Прямое чтение и запросы фото возвращают общий 404 при утрате права. BFF проверяет право на POI и принадлежность медиа этому месту при каждом запросе, включая повторное открытие ранее выданной ссылки.
  3. Необязательная метка. В опубликованный слой попадают явно выбранные глобальные POI. Закрывшуюся метку убирают из слоя, сам разрешённый снимок остаётся видимым. Список меток закрепляется при публикации, а положение каждой разрешённой метки берётся из текущей версии POI.
  4. Зависимость геометрии. Если положение места раскрывается стартом, точкой или производной линией, ревизия маршрута хранит ссылку на точную версию положения POI. Необходимы актуальное право, совпадение с текущей версией положения и её одобрение для публичного чтения. При ограничении карточка, карта и список исключают всю поездку. Одобрение нового положения не открывает старые координаты.
  5. Восстановление. Владелец получает geometry_restricted и только UUID маршрута и его ревизии вместе с признаком ограничения. Для восстановления передай новый состав из разрешённых опор без UUID прежних точек и треков. Если правка переиспользует объекты из прежнего снимка, Geo проверяет их прежние зависимости. Чтобы выставить пересобранный маршрут в GIS-06, владелец публикует новый снимок. Пересборка маршрута

Отзыв применяется к чтениям, обязательная проверка которых началась после его фиксации. Пересекающееся чтение может завершиться по состоянию, разрешённому в момент своей проверки. BFF отдаёт данные, медиа и ошибки доступа с Cache-Control: no-store. PWA исключает эти ответы из Cache Storage. Уже полученные байты остаются у получателя. Состояния после повторной проверки

  • Место или фото недоступно. Обновлённый слой убирает маркер. Карточка и галерея очищают недоступные данные при 404. При отзыве доступа только к фото остальные разрешённые данные места остаются доступны после проверки.
  • Пустая разрешённая выдача. Успешный ответ с пустым списком оставляет карту без подходящих меток. Это обычный результат поиска или фильтра.
  • Маршрут ограничен. Редактор показывает необходимость пересборки без закрытых координат, фото и подробностей об исходном POI. При отказе публикации панель сообщает о недоступной части маршрута. Состояния панели публикации
  • Публичная поездка недоступна. При 404 клиент очищает прежнюю карточку и карту. При 503 скрывает защищённые данные до успешной проверки. При возврате фокуса и периодической проверке видимой карточки применяется последний актуальный ответ.

Для состояний отзыва, пустой выдачи и пересборки описано ожидаемое поведение. Тексты и отдельные макеты уточняются при реализации. Макеты UX-01 · Правила публичного интерфейса

Операции API

Контракт BFF 0.5.0 использует UUID и префикс /api/v1. Для записи нужны сессия tropio_session, разрешённый Origin, X-CSRF-Token и Idempotency-Key в формате UUID. Запросы с телом используют application/json. При неопределённом исходе повтор использует тот же ключ и те же параметры. BFF передаёт Cache-Control: no-store и X-Request-Id. OpenAPI GIS MVP

Ошибки и восстановление

HTTP-отказы используют application/problem+json с type, title, status, code и request_id. При конфликте current_poi_revision_id может возвращаться после проверки действующих прав. Для гостевого запроса скрытого места выдаётся общий 404 без проверки скрытой области в Travel. Коды POC-04 · Ошибки BFF и восстановление
