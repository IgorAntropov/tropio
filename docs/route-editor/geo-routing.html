Точки, треки и расчёт маршрута

Владелец поездки собирает маршрут дня из упорядоченных точек и соседних треков. Geo сохраняет неизменяемые ревизии, строит автомобильные, велосипедные и пешие участки по графу Valhalla и рассчитывает высоты по Copernicus DEM GLO-30 Public. ТЗ, §§ 8–9 · Пилот POC-02

Статус. Серверные операции работают с GIS-04. Карта, схема и состояния сохранения подключены в GIS-05 и находятся на визуальной приёмке. Публикация закреплённых ревизий запланирована на GIS-06. Редактор маршрута дня · OpenAPI 0.4.0

Сценарий и права

  1. Владелец с действующей сессией получает route_id из черновика Travel. Если геометрию ещё не сохраняли, Geo возвращает пустые points и tracks и route_revision_id: null. Привязка маршрута дня
  2. Для выбранных координат и транспорта редактор запрашивает предпросмотр. Для автоматического режима ответ показывает исходные и предложенные координаты обоих концов и фактическое смещение. Если расчёт доступен и предложенные координаты совпадают с текущим положением обоих концов, редактор сохраняет автоматический трек сразу. При новом смещении пользователь подтверждает привязку или выбирает доступную альтернативу. Если расчёт недоступен, редактор показывает причину. Предпросмотр может предложить связный пеший вариант и прямой отрезок с предупреждением о непроверенной проходимости. connection: snapped_finish обозначает продолжение от привязанного конца до исходной точки. Без этого поля альтернатива заменяет весь трек. ТЗ, § 8.3
  3. Редактор отправляет новый состав точек и треков с текущей ревизией. Один трек соединяет каждую пару соседних точек. При переносе общей точки Geo согласует концы связанных треков и может пометить трек needs_rebuild. Тип поездки вычисляется по транспорту на треках всех дней. Несколько видов дают combined.
  4. Если POI закрыта или её положение изменилось, Geo повторно проверяет доступ к точной сохранённой версии. Авторизованный владелец ограниченного маршрута получает geometry_restricted без координат. Чтобы пересобрать маршрут, отправь новый состав из доступных опор без UUID прежних точек и треков. Правила отзыва доступа

По макетам на широком экране карта и схема видны одновременно. На смартфоне они сменяют друг друга, сохраняя выбранный объект. Редактор показывает ожидание рядом с объектом, подтверждает сохранение после ответа BFF и сохраняет ввод при сетевом сбое или конфликте. При конфликте пользователь может сравнить версии или продолжить локальную правку. Макет широкой схемы · Макет мобильной схемы · Состояния редактора

Операции API

API использует UUID и координаты WGS 84. Защищённым запросам нужна cookie tropio_session. Запросы с телом передают Content-Type: application/json, разрешённый Origin и X-CSRF-Token. Записывающие команды также требуют UUID в Idempotency-Key. BFF передаёт Cache-Control: no-store и X-Request-Id. Схемы и точные пары ошибок OpenAPI · Восстановление при сбое

Метод и операцияВход и ответ
GET /api/v1/routes/{routeId}
getRouteDraft		Владелец получает 200 RouteDraft. Результат содержит текущую ревизию, точки и треки или только UUID маршрута и ревизии при geometry_restricted.
POST /api/v1/routing/calculate
previewRouteTrack		Действующая сессия, from, to, transport_mode и необязательный build_mode (по умолчанию automatic). Ответ 200 с available или unavailable. При наличии линии сервер возвращает elevation_profile. Это расчёт без версии маршрута и без ключа команды.
PUT /api/v1/routes/{routeId}
replaceRouteDraft		Владелец передаёт ожидаемую route_revision_id, упорядоченные points и tracks. Для первого сохранения укажи null. Для сохранения привязки отправь у трека confirm_snap с координатами from и to из полей snapped предпросмотра и его graph_version. Ответ 200 содержит подтверждённый снимок. Лимит тела — 256 КиБ.
POST /api/v1/tracks/{trackId}/split
splitTrack		Владелец передаёт UUID маршрута, ожидаемую ревизию и позицию. Ответ 200 SplitResult содержит UUID сохранённой ревизии, общей точки и двух треков. Примеры запроса и ответа
POST /api/v1/routes/{routeId}/restore
restoreRouteDraft		Владелец передаёт текущую route_revision_id и target_revision_id из истории этого маршрута. Geo заново проверяет зависимости целевой ревизии. Ответ 200 содержит восстановленный снимок с новым UUID.

Первый прямой трек

{
  "route_revision_id": null,
  "points": [
    { "position": { "lon": 84.9514, "lat": 56.4846 } },
    { "position": { "lon": 84.9684, "lat": 56.4660 } }
  ],
  "tracks": [{ "build_mode": "straight", "transport_mode": "foot" }]
}

При успешном PUT используй выданные UUID точек, трека и ревизии для следующей правки. Геометрия BFF использует LineString с парами [lon, lat]. При наличии профиля высот трек содержит отсчёты, покрытую дистанцию, источник, версию, вертикальный датум и метод расчёта. Схемы ответа

Очистка маршрута дня

После подтверждения владельцем редактор вызывает PUT /api/v1/routes/{routeId} (replaceRouteDraft, OpenAPI 0.4.0) с ожидаемой ревизией и пустыми массивами. Ниже приведён пример тела для сохранённого маршрута. Ответ 200 содержит новую ревизию с пустым составом. Для отмены и повтора редактор использует POST /api/v1/routes/{routeId}/restore (restoreRouteDraft). Контракт · Проверка состава маршрута

{
  "route_revision_id": "10000000-0000-4000-8000-000000000001",
  "points": [],
  "tracks": []
}

При 409 ROUTE_REVISION_CONFLICT редактор сохраняет локальную версию и предлагает сравнить её с актуальной. При неизвестном исходе из-за сбоя сети пользователь может повторить команду. Клиент при повторе сохраняет тело и ключ Idempotency-Key. Сохранение и конфликт · Восстановление при сбое

Travel владеет привязкой к дню и правами на поездку. Geo владеет снимками геометрии и точными зависимостями от версий положения POI. При делении Geo фиксирует новую ревизию, результат команды и route.track.split в одной транзакции. Данные и событие деления · Публикация и владение данными

Локальные провайдеры

Храни граф, GeoTIFF и локальный манифест вне Git. pnpm dev:all запускает приложения и хранилища Tropio. Граф Valhalla и растры готовятся отдельно. Локальный запуск · Переменные окружения

  • Valhalla. Подготовь региональный OSM PBF, собери граф с valhalla_build_tiles и запусти valhalla_service с той же конфигурацией. Для пилота используй командную последовательность и области из POC-02. Задай TROPIO_VALHALLA_URL (например http://127.0.0.1:18002), TROPIO_VALHALLA_GRAPH_VERSION и TROPIO_VALHALLA_COVERAGE как JSON-массив областей [west,south,east,north]. TROPIO_VALHALLA_SNAP_LIMIT_M по умолчанию 50 м и принимает положительные значения до 50 м. Подготовка графа · Адаптер Valhalla
  • Copernicus DEM GLO-30 Public. Скопируй пилотный манифест рядом с исходными COG, проверь их SHA-256 по манифесту и укажи путь к JSON в TROPIO_DEM_MANIFEST. Он закрепляет версию набора, датум EGM2008 и имена тайлов. Geo проверяет контрольные суммы при чтении и берёт отсчёты с шагом до 30 м. На пропусках высота равна null. При разрыве полного профиля набор и сброс возвращаются как null, а минимум и максимум считаются по доступным отсчётам. Пилотный манифест и условия атрибуции · Данные и метод пилота · Адаптер Copernicus

При недоступной Valhalla автоматический расчёт возвращает 503 DEPENDENCY_UNAVAILABLE. Прямой режим доступен без графа. Если граф отвечает, но подходящего пути нет, предпросмотр возвращает 200 unavailable с причиной no_edge, disconnected или outside_coverage. Сохранение трека без доступного авторасчёта требует выбрать разрешённый вариант. Коды расчёта и сохранения

Приёмка

pnpm db:test:geo входит в pnpm check, создаёт временную базу PostgreSQL/PostGIS и сверяет ответы реального BFF по AT-01–06. HTTP-тесты используют управляемые ответы провайдера для повторяемых проверок. Отдельные тесты адаптера проверяют выбор профиля, разрывы сети и тайлов, высоты и контрольные суммы. HTTP-тесты · Тесты провайдеров · Критерии ТЗ

Запусти TROPIO_GEO_PILOT_CHECK=1 pnpm db:test:geo с настроенными переменными провайдеров для дополнительного сценария на реальных данных. В GIS-04 проверены подтверждение привязки по графу Томска и сохранение профиля Copernicus через BFF. Отдельно проверены расчёты Valhalla для Томска и Чемала и покрытие DEM на контрольных треках Томска, Акташа и Салехарда. Подготовка пилотных данных

  • AT-01. Два автоматических автомобильных трека и прямой пеший трек образуют валидный маршрут и дают тип поездки combined.
  • AT-02 и AT-04. Повторное деление сохраняет порядок и исходную геометрию в истории. Перенос общего узла согласует два соседних трека или помечает участок для пересчёта. Деление и история
  • AT-03. Предпросмотр сохраняет исходную координату удалённой от дороги точки. Клиент получает доступные альтернативы или ошибку зависимости. Дорожная привязка сохраняется после подтверждения.
  • AT-05 и AT-06. Две поездки ссылаются на один UUID POI. Отзыв доступа к POI скрывает её и ограничивает зависимую геометрию. Приёмка приватности POI
