Команды запуска

Выполняй команды из корня репозитория при работающем Docker и заполненном локальном .env. Команды workspace · Конфигурация Compose

  • pnpm dev:all поднимает сервисы Compose, ждёт готовности до 180 секунд, запускает pnpm db:migrate, загружает новые версии демоданных и запускает NestJS и Nuxt. Для незаданного TROPIO_IDENTITY_DATABASE_URL, TROPIO_TRAVEL_DATABASE_URL или TROPIO_GEO_DATABASE_URL скрипт создаёт временную учётную запись PostgreSQL с ролью соответствующего сервиса и удаляет её при завершении. При ошибке миграций приложения не запускаются. Скрипт локального запуска · Отдельный запуск провайдеров Geo
  • Для запуска собранного приложения локально выполни pnpm build, затем pnpm start:all. Этот запуск также поднимает Compose, применяет миграции и загружает демоданные. Чтобы обновить уже работающий стенд, выполни pnpm db:migrate, затем pnpm db:demo. Вход под тестовым пользователем
  • pnpm db:migrate применяет миграции к локальной базе через psql в уже запущенном сервисе postgres. Подключение использует административную учётную запись контейнера.
  • pnpm db:test:migrations использует тот же запущенный контейнер и отдельные временные базы для проверки миграций.
  • pnpm db:test:identity создаёт временную базу, применяет миграции и запускает HTTP-тесты Identity с временной учётной записью. Команда входит в pnpm check. Если PostgreSQL ещё не запущен, выполни docker compose up -d --wait postgres. Приёмка Identity
  • pnpm db:test:travel создаёт отдельную временную базу, применяет миграции и запускает HTTP-тесты Travel с прикладными подключениями Identity и Travel. Команда входит в pnpm check и требует работающего сервиса postgres. Приёмка Travel
  • pnpm db:test:publication проверяет публикацию, конкурентные команды и отзыв доступа к каталогу на временной базе с подключениями Identity, Travel и Geo. Команда входит в pnpm check. Сценарии GIS-06
  • pnpm db:test:geo создаёт отдельную временную базу, применяет миграции и запускает HTTP-тесты Geo с отдельными прикладными подключениями Identity, Travel и Geo. Команда входит в pnpm check и требует работающего postgres. Приёмка Geo

Данные демостенда и их обновление

На чистой базе загрузчик подготавливает тестового путешественника, профиль турфирмы, поездки и маршруты дней. Он выполняет операции Identity, Travel и Geo, затем публикует выбранные версии поездок и их маршрутов. Локальное приложение и статический каталог GitHub Pages используют общие UUID поездок. Состав первой версии · Загрузка поездок и публикация

После перезапуска Docker с тем же томом завершённые версии пропускаются. Поездки, созданные вручную, и правки пользователя сохраняются. Миграция Travel 0008 создаёт журнал travel.local_demo_versions с номером версии, именем файла, контрольной суммой SHA-256 и временем начала и завершения загрузки. Параллельные запуски применяют версии по очереди. Если загрузка прервалась, устрани причину и повтори pnpm db:demo. Загрузчик продолжит незавершённую версию по её исходному файлу. Схема журнала · Проверка истории и повтор загрузки

Версия демоданных 0003-personal-equipment.json заполняет «Мои вещи» тестового путешественника через Travel. Шесть предметов показывают три варианта размещения — без группы, в группе и в подгруппе. Для каждого есть пример с иконкой и без неё. При совпадении названия и несовместимых деталях загрузчик сохраняет ручную запись и подбирает для примера название с суффиксом. Сборка публичного каталога GitHub Pages исключает данные личных вещей. Как проверить личный инвентарь · Загрузчик Travel

Версия 0004-personal-trips.json добавляет частный архивный черновик и заполняет подборки тестового путешественника через операции Travel. Для доступных поездок с открытым набором создаются примеры заявки и подтверждённого участия, одна публикация попадает в избранное. Повторный запуск сохраняет ручные изменения. Сборка GitHub Pages исключает личные записи этой версии. Как проверить подборки · Проверки установки и обновления

Версия 0005-personal-travelers.json создаёт через Identity четыре профиля. Версия 0006-personal-journeys.json добавляет в локальный каталог опубликованные поездки разных организаторов. Среди них есть путешествия, которые скоро начнутся, уже идут, завершены и отменены. В программе одной из своих поездок тестовый путешественник видит две заявки и двух подтверждённых участников. В других подборках есть чужая поездка в избранном, заявки и участие. После повторной загрузки вручную снятая отметка и решение по участнику сохраняются. Статическая демонстрация GitHub Pages использует только публичный набор демоданных. Проверка состава группы · Проверка версий демостенда

Версия 0007-personal-avatars.json назначает пяти локальным демопрофилям разные аватары из действующего набора Identity. Сервис обновляет активный профиль только при исходной стандартной картинке и неизменённых с создания настройках. Выбранная вручную картинка, загруженное фото и правки профиля сохраняются при обновлении стенда. Условия замены в Identity

Когда меняются сценарии или модель данных демостенда, добавь в fixtures/demo/ следующий файл, например 0008-add-trip.json с полем version: 8. Используй последовательные номера. Для каждой новой поездки укажи уникальные UUID и slug. Сборка GitHub Pages читает из этих версий данные поездок для публичного каталога. Сохраняй имена и содержимое выпущенных файлов, включая пробелы. Изменение применённого файла останавливает локальную загрузку из-за расхождения контрольной суммы. Сверь организаторов, публичные поездки и личные черновики локально и в сборке pnpm --filter @tropio/frontend run generate:pages. Команда pnpm db:test:demo входит в pnpm check и проверяет на временной базе гостевой каталог и маршруты, приватность черновика, ручные правки, конкурентный запуск и продолжение прерванной версии. Прикладная роль читает справочник категорий, а добавление и редактирование категорий выполняются миграциями. Журнал связывает сохранённый результат с точной ревизией POI. Высоты треков · Категории и команды POI

У каждого домена есть владелец tropio_<service>_owner и прикладная роль tropio_<service>_runtime. Обе роли имеют NOLOGIN. Исполнитель выполняет доменный SQL от роли владельца. Прикладной роли выдаются права на данные своей схемы без права создавать в ней объекты. Между схемами остаются ссылки по UUID, а внешние ключи действуют внутри схемы владельца. История, транзакция и сбои

Служебная таблица tropio_migrations.applied доступна администратору и хранит владельца, номер версии, имя файла, SHA-256 его содержимого и время применения. Прикладные роли доступа к схеме журнала не получают. Перед изменением доменных схем исполнитель проверяет непрерывность истории и соответствие имён и контрольных сумм файлам. Журнал и проверка истории

Исполнитель применяет ожидающие миграции и записывает их в журнал в одной транзакции под блокировкой PostgreSQL. Повторный запуск пропускает уже применённые версии. При ошибке SQL изменения текущего запуска и его записи журнала откатываются вместе. Если имя или содержимое файла применённой версии изменилось, исполнитель останавливается. Восстанови исходный файл и добавь следующую версию в каталоге владельца. Вызов psql

Проверочные базы

  1. Скрипт создаёт чистую временную базу из template0, устанавливает PostGIS через миграцию, проверяет схему, права и ограничения, затем повторяет запуск без новых записей журнала.
  2. Во второй временной базе скрипт заранее устанавливает PostGIS и применяет текущие миграции. После добавления проверочной записи он создаёт искусственную следующую миграцию во временной копии файлов.
  3. Искусственная ошибка проверяет откат схемы и журнала. Исправленный тестовый файл проверяет обновление с сохранением данных и безопасный повтор. Изменение применённого тестового файла проверяет отказ при несовпадении SHA-256.

Проверочные базы удаляются после прогона. Искусственное обновление проверяет переход от текущего набора файлов к следующей версии в тесте. Сценарии проверки · Контрактные проверки SQL · Модель в ТЗ
