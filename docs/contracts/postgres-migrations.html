Миграции PostgreSQL и PostGIS

Локальный запуск Tropio применяет версионированные миграции PostgreSQL перед запуском приложений. GIS-01 закладывает SQL-хранилища Identity, Travel и Geo и права доступа к ним. Операции аккаунта, путешествия, маршрута и публикации реализуются в следующих задачах GIS-02 и далее. Бэклог GIS MVP · Проект POC-04

Команды запуска

Выполняй команды из корня репозитория при работающем Docker и заполненном локальном .env. Команды workspace · Конфигурация Compose

  • pnpm dev:all поднимает локальные сервисы через Compose, ждёт готовности до 180 секунд, запускает pnpm db:migrate и после успеха запускает NestJS и Nuxt. При ошибке миграций запуск приложений прерывается.
  • pnpm db:migrate применяет миграции к локальной базе через psql в уже запущенном сервисе postgres. Подключение использует административную учётную запись контейнера.
  • pnpm db:test:migrations использует тот же запущенный контейнер и отдельные временные базы для проверки миграций.

Миграции и роли по владельцам

Файлы лежат в backend/migrations/. В каждом каталоге владельца нумерация начинается с 0001 и продолжается без пропусков. Скрипт применяет каталоги в порядке таблицы. Исполнитель миграций

КаталогПервая версия
platformГотовит PostGIS в public, доменные схемы и роли. SQL
identityПользователи, способы входа, сессии, служебные записи подтверждения и каталог системных аватаров. SQL
travelПутешествия, дни, привязки маршрутов, журналы операций, снимки публикации, проекция каталога и outbox. SQL
geoГеометрия и её ревизии, точки, треки, POI и версии положения, зависимости маршрута, удержания ревизий и outbox. SQL

У каждого домена есть владелец tropio_<service>_owner и прикладная роль tropio_<service>_runtime. Обе роли имеют NOLOGIN. Исполнитель выполняет доменный SQL от роли владельца. Прикладной роли выдаются права на данные своей схемы без права создавать в ней объекты. Между схемами остаются ссылки по UUID, а внешние ключи действуют внутри схемы владельца. Travel фиксирует состав операции до запроса удержания Geo. Geo фиксирует ревизию маршрута до установки её как текущей или выдачи удержания. SQL защищает закреплённый состав, геометрию и версии положения POI от изменения прикладной ролью. Публикация Travel/Geo · Приватность POI

История, транзакция и сбои

Служебная таблица tropio_migrations.applied доступна администратору и хранит владельца, номер версии, имя файла, SHA-256 его содержимого и время применения. Прикладные роли доступа к схеме журнала не получают. Перед изменением доменных схем исполнитель проверяет непрерывность истории и соответствие имён и контрольных сумм файлам. Журнал и проверка истории

Исполнитель применяет ожидающие миграции и записывает их в журнал в одной транзакции под блокировкой PostgreSQL. Повторный запуск пропускает уже применённые версии. При ошибке SQL изменения текущего запуска и его записи журнала откатываются вместе. Если имя или содержимое файла применённой версии изменилось, исполнитель останавливается. Восстанови исходный файл и добавь следующую версию в каталоге владельца. Вызов psql · Правила миграций Tropio

Проверочные базы

  1. Скрипт создаёт чистую временную базу из template0, устанавливает PostGIS через миграцию, проверяет схему, права и ограничения, затем повторяет запуск без новых записей журнала.
  2. Во второй временной базе скрипт заранее устанавливает PostGIS и применяет текущие миграции. После добавления проверочной записи он создаёт искусственную следующую миграцию во временной копии файлов.
  3. Искусственная ошибка проверяет откат схемы и журнала. Исправленный тестовый файл проверяет обновление с сохранением данных и безопасный повтор. Изменение применённого тестового файла проверяет отказ при несовпадении SHA-256.

Проверочные базы удаляются после прогона. Искусственное обновление проверяет переход от текущего набора файлов к следующей версии в тесте. Сценарии проверки · Контрактные проверки SQL · Модель в ТЗ
